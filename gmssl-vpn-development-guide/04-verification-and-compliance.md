# 第 4 章：验证与符合性

> 本章回答：怎样判断实现正确，并且能够说明它覆盖 GM/T 0024-2023 的目标要求？

## 本章目标

开发完成后，不能只用“能连接、能 ping、能访问网页”来判断 GMSSL VPN 已经完成。可用性只说明系统跑起来了；符合性还要求协议、密码、VPN 功能、产品安全和检测证据都能对应到标准。

本章只建立一套简明验收框架，不展开详细测试用例。详细用例、抓包样例、配置样例和符合性矩阵放到附录或配套测试文档中。正式符合性结论应以适用的产品检测和判定程序为准。

## 4.1 三层验收口径

验收时先分清三层结果：

| 层次 | 关注问题 | 不能替代什么 |
|---|---|---|
| 协议正确 | TLCP、记录保护、密码套件、密钥和报警行为是否符合预期 | 不能替代 VPN 产品能力 |
| VPN 可用 | TUN、路由、会话、转发和访问控制是否形成完整通路 | 不能替代标准完整覆盖 |
| 符合性可复核 | 标准要求是否都有设计、实现和验证证据 | 不能只靠口头说明 |

最小追踪关系如下：

```text
标准要求
→ 设计位置
→ 实现位置
→ 验证方式
→ 验证结果
```

只要其中任何一环缺失，就只能说“功能已有进展”，不能说“要求已经闭环”。

## 4.2 按 GM/T 0024-2023 第 5 章验收：密码算法与密钥

第 5 章重点看密码和密钥是否按标准进入系统。

应至少检查：

| 验收项 | 通过标志 |
|---|---|
| 密码算法与套件 | 标准要求的密码套件有支持矩阵，能说明已支持、待支持和不适用状态 |
| 双证书 | 签名证书、加密证书的加载、验证和使用路径清楚 |
| 随机数 | 随机数来源、硬件噪声源和产品路径边界清楚 |
| 密钥层次 | 预主密钥、主密钥、双向工作密钥和记录保护密钥语义不混淆 |
| 工作密钥更新 | 同时支持时间和流量触发；更新 TLCP 安全参数并按第 6.5 节计算、切换新工作密钥；客户端—服务端按时间更新最长不超过 8 小时，网关—网关最长不超过 1 小时 |
| 密钥销毁 | 断连、断电或实例释放时，工作密钥和敏感临时数据能被清理 |

开发阶段可以用 GmSSL 软件后端验证协议行为；产品符合性结论则需要明确独立密码部件和随机数来源。

## 4.3 按 GM/T 0024-2023 第 6 章验收：协议

第 6 章重点看线上协议是否符合标准。

应至少检查：

| 验收项 | 通过标志 |
|---|---|
| TLCP 版本 | 使用 TLCP 1.1，线上版本值为 `0x0101` |
| 握手流程 | 客户端和服务端能够完成协商、证书验证、密钥计算和握手完成 |
| 记录层 | 握手、报警、密码规格变更、应用数据等记录类型处理正确 |
| 记录保护 | CBC 和 GCM 记录保护路径有验证结果 |
| 异常处理 | 认证失败、记录校验失败、套件不匹配、换钥失败时安全关闭 |
| 网关—网关 | 产品声明支持该模式时，`site2site(80)`、command/data 和保护域绑定有验证证据 |

客户端—服务端模式下，本指南设计的 VPN 载荷放在 TLCP `application_data` 中；产品声明支持网关—网关模式时，使用标准 `site2site` 路径。

## 4.4 按 GM/T 0024-2023 第 7 章验收：产品要求

第 7 章重点看 SSL VPN 是否成为完整产品能力，而不是单条安全连接。

应至少检查：

| 验收项 | 通过标志 |
|---|---|
| 客户端—服务端模式 | 终端能通过服务端访问受保护网络和 Web 资源 |
| 网关—网关模式 | 产品声明支持该模式时，两端网关按保护域传输完整 IP 包 |
| 会话绑定 | VPN 接入会话、TLCP 连接和密码状态边界清楚并保持一致绑定 |
| 访问控制 | 支持按用户或用户组控制 IP、端口、URL 和访问时间 |
| 安全管理 | 管理员、配置、证书密钥、日志、监控、初始化和自检能力清楚 |
| 软件安全 | 安全协议和管理软件具有自主实现、审查和维护证据；操作系统完成安全加固，定型产品封闭调试与检测接口 |
| 失败安全 | 认证、策略、换钥、连接异常时不会绕过安全控制 |

这一章的验收重点是“安全关系是否闭合”。如果服务端只根据虚拟源地址转发，而不是根据认证会话和策略转发，就不应认为访问控制已经完成。

## 4.5 按 GM/T 0024-2023 第 8 章验收：检测要求

第 8 章重点看验证证据是否能够复核。

应至少保留：

| 证据 | 用途 |
|---|---|
| 协议证据 | 握手、套件、记录保护、报警和换钥结果 |
| 功能证据 | 客户端—服务端、多客户端、访问控制和异常处理结果；声明网关模式时包括网关—网关结果 |
| 安全证据 | 密码部件、随机数、密钥销毁、日志、自检和管理控制结果 |
| 性能证据 | 最大并发连接数、每秒新建连接数、最大并发用户数和加解密吞吐率的测量结果 |
| 追踪证据 | 标准要求、设计、实现和测试结果之间的对应关系 |

这些证据不要求全部堆在正文里，但必须能够被找到、被复核、被更新。

## 4.6 按 GM/T 0024-2023 第 9 章形成判定

产品检测结果必须按第 9 章汇总结论。标准明确规定：第 8.1 节和第 8.3 节（8.3.1.2 除外）中的任意一项不合格，判定为产品密码检测不合格。因此，功能或性能亮点不能抵消安全管理与密码检测中的失败项。

开发阶段应把这一规则转化为发布门禁：判定范围内的每个项目都有明确结果，失败项关闭后才能进入正式发布或送检版本。

## 4.7 最小验收清单

进入“完成”判断前，至少回答下面九个问题：

1. 第 5 章的密码算法、套件、随机数、双证书、密钥更新和密钥销毁是否有证据？
2. 第 6 章的 TLCP 版本、握手、记录、报警和记录保护是否有证据；声明网关模式时，`site2site` 路径是否有证据？
3. 第 7 章的客户端—服务端、访问控制、安全管理和自检是否有证据；声明网关模式时，网关—网关能力是否有证据？
4. 第 8 章要求的功能、安全、性能和检测结果是否能复核？
5. 目标通信路径是否已经与 OpenVPN 私有线上协议分离？
6. GmSSL 的能力是否逐项核验，而不是默认等同于标准完整实现？
7. 每个业务报文是否都能追溯到有效 VPN 接入会话和访问策略？
8. 断连、异常、换钥失败和实例释放时，密钥和资源是否能够安全清理？
9. 第 9 章判定范围内是否不存在尚未关闭的不合格项？

如果九个问题都有明确证据，才可以进入更正式的符合性矩阵整理；如果只能回答其中一部分，就继续回到第 3 章对应阶段补齐。

## 本章结束时

读者应当能够区分三句话：

```text
系统可以运行
系统功能完整
系统对 GM/T 0024-2023 的关键要求有可复核证据
```

本指南的目标，是帮助开发者沿着这三句话逐步前进，而不是在第一个结果出现时就过早宣布完成。

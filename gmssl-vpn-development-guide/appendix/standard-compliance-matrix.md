# 附录 B：标准符合性追踪矩阵

> 本附录用于记录 GM/T 0024-2023 的要求怎样落到设计、实现和验证证据。它是工程追踪工具，不替代标准正式文本。

## B.1 使用方式

每一项要求沿同一条链路追踪：

```text
标准条款 → 设计位置 → 实现位置 → 验证方式 → 证据位置 → 当前状态
```

状态统一使用：

| 状态 | 含义 |
|---|---|
| 未开始 | 尚未形成设计或实现 |
| 设计中 | 已有设计位置，实现和验证尚未完成 |
| 实现中 | 已有代码或配置，验证证据尚未闭环 |
| 已验证 | 已有可复核的通过结果 |
| 不适用 | 经产品范围和标准条款分析确认不适用，并已记录理由 |

“不适用”必须写明产品范围、判断依据和批准人，不能用来回避标准要求。

## B.6 填写原则

1. 先填设计位置，再填实现位置，最后关联验证证据；
2. “已验证”必须同时具有测试环境、步骤、实际结果和证据位置；
3. GmSSL 或 OpenVPN 的上游能力只能作为输入，不能替代目标实现自身的证据；
4. 软件参考后端与产品密码部件分别记录，不混用结论；
5. 每次设计、代码、密码部件或标准基线变化后，重新评估受影响的矩阵项；
6. 不复制标准原文，条款解释存在分歧时回到合法取得的正式文本核对。
